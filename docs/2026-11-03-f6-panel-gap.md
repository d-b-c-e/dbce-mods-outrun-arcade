# CannonBall F6 panel gap and integration design

Read-only source audit, assignment506861; docs-only disposition confirmed by
kole506901. Audited local master `5f2c16f27ff5d253610fa7b64077ad90bffcb9ef`.
No panel, shortcut, source change, build, game, install or device test is delivered
by this note. A complete SDL2/GLES panel host is an owner scope decision.

## Finding

There is no F6 mapping or shared settings panel in this source. The cabinet
frontend already offers video, sound, controls, engine and save menus, including
the saved wheel picker, but it is a game mode rather than a resumable overlay.
Its existence does not satisfy STD-030's shared F6 panel shape.

| Consumer | Source finding | Consequence |
|---|---|---|
| [SDL key handler](../src/main/sdl2/input.cpp), `Input::handle_key` | F5 sets MENU; F7 toggles sprite rendering; F8 changes CRT/filter configuration; F9 toggles mask behavior. No F6 case. | F6 has no panel action. The existing F8 function conflicts with the shared Stop FFB convention and needs an explicit migration design. |
| [Host loop](../src/main/main.cpp), `process_events` / `tick` | SDL key events enter Input; MENU during STATE_GAME requests STATE_INIT_MENU. That state initializes input/output and calls `Menu::init`. | An F6-to-MENU alias would take the destructive frontend transition. |
| [Frontend](../src/main/frontend/menu.cpp), `Menu::init` | Selects course, resets sprite/tile/road state and car increment, assigns guest GS_INIT, clears external music and initializes sound. | It cannot preserve an interrupted race just by changing its initial page. |
| Same frontend, `Menu::set_menu` / `menu_back` | Push/pop cursor and page pointers within the frontend. | These preserve only frontend navigation, not guest/renderer/audio state. A frontend-only F6 shortcut would still not provide the required in-race panel. |
| [Presenter](../src/main/sdl2/rendersurface.cpp), initialization / `finalize_frame` | Requests SDL OpenGL ES2, prefers ANGLE/GLES, draws CRT/postprocessing, then calls glb::present. | A D3D swap-chain overlay cannot simply be attached to this presenter. |
| Same presenter, `disable` | Waits for active frames and takes GPU/context ownership before glb shutdown, context deletion and window destruction. | Panel renderer resources must join this lifecycle and be recreated with the context. |
| [Config writer](../src/main/frontend/config.cpp), `Config::save` | Updates the settings tree broadly and serializes XML. | It is not demonstrated to preserve unrelated original bytes. New panel writes need an owned-key transaction rather than an unqualified full save. |

The force-active gate checks STATE_GAME, pause and GS_INGAME. The separate rumble
branch checks skidding/game state and motor output. A future panel must fence
both; adding only the force-active condition would leave another output route.

## Reuse and smallest complete design

Toolkit source inspected at `17f3aa2556406a09fcacab48684d5b544872d941`:
[shared panel contract](E:/Source/toolkits/dbce-wheel-mod-toolkit/native/panel/dbce_panel.h).
It already owns the standard title, Simple/Advanced view, Close, Stop FFB, fixed
Controls/Force feedback/Cameras/Telemetry/Help order, hidden unsupported pages and
widgets. The inspected vendored ImGui backend directory contains Win32 and
DX9/DX11/DX12 backends; it contains no SDL2/OpenGL backend. This is an observation
of the local toolkit, not a claim that no compatible external backend exists.

The smallest complete route reuses that panel body and adds the missing host:

1. Adapt the existing SDL2 window/events and GLES2 presentation to the same panel
   contract, pinning any required backend to the toolkit's ImGui version. Draw
   after game/CRT composition and before `glb::present`, in physical window
   coordinates, so panel text does not inherit CRT warp/mask. Use the actual
   center racing-display rectangle when spanning; wide-window center alone
   does not qualify centered menus on arbitrary layouts.
2. Keep panel event delivery and drawing on an explicitly owned thread/context.
   The presenter has GPU/worker locks; an event hook must not concurrently mutate
   ImGui state. Destroy renderer resources before context shutdown and reinitialize
   them after the next valid window/context. No second native window is needed.
3. F6 opens/closes without entering STATE_INIT_MENU or calling `Menu::init`.
   While open, suppress driving/key-remap shortcuts, pause guest advancement,
   neutralize force and rumble, and retain prior manual pause state. Close restores
   that state without synthesizing a key/button press or resetting the race.
   Define F8 Stop FFB and relocation of the existing CRT shortcut together.
4. Start with only implemented pages/settings; Help remains. Existing wheel,
   force and telemetry consumers are integration candidates, not automatically
   qualified panel rows. Hide unsupported camera/triple controls and never label
   a wide sprite span as three projected views. Simple/Advanced follows the shared
   contract from the first host increment.
5. Route each edited setting through its real consumer and an owned-key XML
   transaction preserving unrelated bytes/encoding/comments/newlines. Preserve
   saved force choice; opening the panel never enables output or saves defaults.
   The panel's own INI preference API needs explicit adaptation to this XML
   product contract, rather than introducing a second conflicting settings file.

This design is not a compiler/API compatibility result. No external package was
downloaded and no reusable host was added to the toolkit in this audit.

## Evidence gates for a later implementation

Focused inert checks should cover actual F6 edge/release and input suppression,
pause-state restoration, both output fences, terminal/context recreation behavior
and unknown-byte/no-op/failure preservation in the real writer. A CPU GO should
state exact compiler scope, bounded job containment and independent cleanup audit.

A separately authorized muted live interval should then establish actual panel
rendering, center placement, key/mouse handling, save/restart consumption and
race continuity across open/close. Fixture/build success alone cannot establish
those observations. Physical input/force, CRT preference, seated geometry and
owner acceptance remain distinct. Existing owner-ready Surround/telemetry rows
and the retained provider-free payload/evidence are unchanged.

STD-004 stays partial; STD-030 is now explicitly pending. Current ledger entries
missing from the previous adoption file were029–032 and036–049. Only030 is touched
by this gap record; other missing/unchecked/pending adoption remains unqualified.
No new family-wide standard, public push or installed-state claim is introduced.
